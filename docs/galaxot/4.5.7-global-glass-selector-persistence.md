# 4.5.7 — Global Galax Glass selection, DataStore and live composition

**Repository:** `SrYorjs/OpenTune-SY` · **Branch:** `opentune-rebuild-v1`
**Scope:** five selectable materials, persistence, migration from legacy toggle, mode propagation, capture-layer ownership, regression.

## Appearance contract

`AppearanceSettings.kt` now exposes **one** `EnumListPreference<GlassMode>` in Appearance:

- `FROSTED`: high diffusion, no lens/vibrancy
- `CLEAR`: transparent glass with lens and optical edge
- `BLUR`: deep blur, no refraction lens/vibrancy
- `CLASSIC`: original Liquid Glass/Sky/Kyant preset compatibility
- `DISABLED`: fully opaque glass component with no shader/capture

Strings are localized in English and Spanish, other locale folders use default English fallback.

## Backward-compatible storage

The new DataStore key `GalaxGlassModeKey` is `stringPreferencesKey("galax_glass_mode")`, in the existing `settings` DataStore.

- **No key** (or empty/invalid key): `parseGalaxGlassMode` returns null. The original `LiquidGlassNavBarKey` remains the source of truth: true => Classic, false => Disabled. There is no unconditional migration write or reset of existing user data.
- **Explicit user selection**: `AppearanceSettings` atomically writes both `GalaxGlassModeKey = mode.name` and legacy `LiquidGlassNavBarKey = mode != DISABLED` in one `dataStore.edit` transaction. Older releases can still interpret the equivalent enabled/disabled state.
- **Restart**: `rememberPreference` observes DataStore changes, so switching modes recomposes the scaffold; selected material persists across process death/restart.
- Unknown values degrade to legacy preference and never crash enum decoding.

## Shared composition

`MainActivityScaffold.kt` is the only global owner:

```text
DataStore(settings)
  ├── legacy LiquidGlassNavBarKey
  └── GalaxGlassModeKey
        │
        ├── parseGalaxGlassMode
        ├── isGalaxGlassEnabled
        └── CompositionLocalProvider
              ├── LocalGalaxGlassMode
              ├── LocalEnableLiquidGlass
              ├── LocalSky (existing)
              └── LocalLiquidBackdrop (new materials only)
                       │
           ┌───────────┴────────────┐
       FloatingNavigation       MiniPlayer
           and other shared GlassSurface consumers
```

**Critical Android 17 crash recovery (17 Oct 2026)**: A Samsung S24 FE running Android 17 crashed immediately after selecting a new mode. The supplied Logcat shows `Fatal signal 11 (SIGSEGV)` in `RenderThread`, with a native stack-overflow indication and hundreds of repeating `libhwui.so RenderNode::prepareTreeImpl / SkiaDisplayList::prepareListAndChildren` frames. This is consistent with an unsafe recursive capture/render graph after attaching Kyant `rememberLayerBackdrop` and `Modifier.layerBackdrop` to `NavHost`. Causal attribution to the exact layer remains a strong working hypothesis until isolated device testing.

**Emergency fix**: `MainActivityScaffold` no longer creates or attaches the Kyant captured layer, and supplies `LocalLiquidBackdrop provides null` to every consumer. Frosted/Blur use theme-aware non-capturing tint, gradient, and outline; Clear uses safe material fallback (with more transparency), and on Android **API 37+** also avoids the unvalidated Sky static lens. Android 33–36 may still use the existing static Sky optical lens for Clear. Classic keeps its original Sky/Cloudy implementation. Disabled remains fully opaque. No user DataStore reset is performed; a previously persisted broken new mode will reopen in the safe rendering path after updating the APK.

**Important**: During this recovery, **Frosted, Clear and Blur do not provide real live backdrop blur/refraction** in the default shell; shader-free materials preserve appearance differentiation, legibility and stability. Restoring real optics requires a separately designed bounded capture tree or offscreen pass, RenderThread crash tests on Android 17, and runtime capability gating/rollback. Do not re-enable the old NavHost capture simply because Android version is high.


## Guardrails

- Do not change `applicationId`, signing, Media3, lyrics, download database, offline cache, search providers, Together or player V1–V8.
- Do not delete/rename the legacy setting. No clearing DataStore on upgrade.
- Theme light/dark, pure-black, artwork dynamic palette and accessibility/reduced motion must remain compatible.
- No visually hidden switch with conflicting state: the old on/off setting is mirrored internally and the five-mode selector is the only visible Glass control.
- Global mode is applied to existing nav and MiniPlayer through the central `LocalGalaxGlassMode`; settings can be left and revisited without losing state.
