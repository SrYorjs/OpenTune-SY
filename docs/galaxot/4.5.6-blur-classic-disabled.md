# 4.5.6 — Blur, Classic and Disabled: full implementation review

**Branch:** `opentune-rebuild-v1` · **Dependency:** 4.5.4, revised 4.5.5.

## Three material paths

| Path | Live backdrop | Static fallback | Disabled behavior |
|---|---|---|---|
| **Blur** | Kyant blur 18 dp, without vibrancy or lens; softly tinted + subdued rim | Theme-based near-opaque tint with sheen and rim, no static lens/shader | n/a |
| **Classic** | Unmodified Kyant vibrancy/blur/lens with old `GlassPreset`, Design System color, shadow and highlight | Original Sky static lens where SDK and budget allow | Legacy on/off preference unchanged |
| **Disabled** | None | None | `GlassSurface`: clipped opaque theme surface and border. `Modifier.galaxGlassEffect`: opaque background only when explicitly selected, preserving legacy no-op when old toggle is off. |

## Stability guarantees

- `CLASSIC` passes **null material overrides** to the canonical engine; `GlassPreset.SOFT` survives in Navigation/MiniPlayer as before. This is visual and binary-behavior compatibility, not a copy of the previous engine.
- `BLUR` never executes the static liquidGlass lens: planner returns `TINT_AND_OUTLINE`; live renderer skips both lens and vibrancy. No secondary RenderEffect allocation.
- `DISABLED` selects `OPAQUE`, never draws Backdrop/Sky lens. The global selection can disable glass even if the old Boolean was enabled.
- No changes to Media3, sources, downloads, queue, player layouts V1–V8, Together or notification session.
- Theme colors are provided from active Material 3, including pure-black handling; reduced motion, low-RAM, battery saver and scrolling remain covered. LOW tier strips gradient and directional rim overlays.
- `isGalaxGlassEnabled` and `resolveGalaxGlassSpec` make selector behavior deterministic without persisting any new key before 4.5.7.

## Validation and remaining work

Tests check real mode precedence, fallback choices, optical differentiation, Classic retained presets, Disabled suppression, and theme-dependent tint. The 4.5.7 settings UI and DataStore migration have **not** been implemented here; there is no visible five-choice switch yet.
