## Variantes: no omitir estilos que realmente siguen persistidos

`PlayerDesignStyle` tiene **V1, V2, V3, V4, V5, V6, V7 y V8**. Por tanto, además de las seis variantes pedidas para auditoría, hay que proteger V4 y V6. `BottomSheetPlayer` usa ramas especiales para V5, V7 y V8 en orientación vertical y horizontal; otras variantes reutilizan componentes generales. `PlayerPlaybackControls` y `Queue` también usan switches por versión. No suponer equivalencia de diseño entre las ramas.

- **V1**: rama histórica de controles y cola, puede compartir parte de V5.
- **V2**: controles específicos y fila/cola colapsada propias.
- **V3**: agrupa parte de controles con V5; validar composición antes de migrar.
- **V4/V6**: variantes válidas del enum, con paths compartidos en componentes. No borrarlas por no figurar en el título.
- **V5**: fondos y layout diferenciados, especialmente landscape.
- **V7**: backdrop propio, slider/progreso/formato diferenciado, landscape y portrait.
- **V8**: diseño predeterminado actual (`defaultValue = PlayerDesignStyle.V8`), `V8PlayerBackdrop`, `V8PlayerControlsContent`, slider/volume/buttons/queue particulares.

## Límites arquitectónicos que Fase 4 debe respetar

```text
MusicService / Media3 / SourceResolver / QueueController   (sin duplicar)
                ↑
         PlayerConnection      ← sigue siendo la puerta playback
                ↑
        PlayerState + PlayerActions     (Fase 4 futura)
                ↑
             PlayerHost
                ↓
  PlayerLayout + VisualSkin → Design System / GlassSurface
                ↓
   shared artwork / controls / queue / lyrics host
```

La fase NO debe implementar un segundo player Media3, migrar la lógica de descargas, cambiar SourceResolver ni rehacer Audio Intelligence/Together/Lyrics 2.0. El playback invitado de Together no debe saltarse: `PlayerConnection.seekToNext/Previous` hace routing especial para guest. Las UI que llaman directamente a `player.seekToNext()` requieren inventario antes de unificarse.

## Contratos de estado y preferencias — NO renombrar ni cambiar defaults

- `PlayerDesignStyleKey` = `playerDesignStyle`; default **V8**.
- `PlayerBackgroundStyleKey` = `playerBackgroundStyle`; default **DEFAULT**.
- `QueueEditLockKey` = `queueEditLock`; default actual **true**.
- `AutoLoadMoreKey` = `autoLoadMore`; default actual **true**.
- `SwipeThumbnailKey` = `swipeThumbnail`; default actual **true**.
- `SwipeSensitivityKey` = `swipeSensitivity`; leer default real del mini-player antes de migrarlo.
- Fullscreen `player_fullscreen`, codec `show_codec_on_player`, canvas/blur, artwork custom, seek extra seconds, tamaño/restricciones de queue deben permanecer compatibles.

## Contratos de interacción críticos

| Subsystem | Estado actual / invariante a conservar |
| --- | --- |
| Play/pause | `togglePlayPause()` prepara player idle cuando hace falta; reinicio de cola con cola terminada en ciertos layouts |
| Skip | PlayerConnection centraliza skip y trato especial Together guest |
| Seek | No hacer seek real por cada frame al arrastrar; commit de seek al terminar |
| Swipe mini | RTL invierte dirección; skip solo si hay previous/next disponible; threshold auto por sensibilidad y/o distancia + velocidad; settle de offset al cancelar y terminar |
| Queue | Reordenación condicionada por lock y shuffle; selection, remove, auto-load, repeats y contexto |
| Transiciones | Motion presets del Design System, evitando regresión de portada/texto |
| Lifecycle | Fullscreen, AOD, media session y notificación no dependen de cambiar layout |
| Canvas/Lyrics | Mantener animación y descarga offline, overlay, cambio de pista y sincronización |

## Zonas de duplicación y prioridad de refactor posterior

1. `PlayerPlaybackControls`: múltiples implementaciones play/pause + previous/next + shuffle/repeat por versión (prioridad 4.8).
2. `Player.kt`: fondos, orientación y top-level layout por estilo (4.4–4.7, 4.13–4.16).
3. `Queue.kt`: contenido colapsado, controles y paneles por estilo (4.10 y migraciones).
4. Slider estilos y progreso en varias superficies (4.9).
5. Artwork/Canvas/background específicos repetidos (4.7).
6. Compatibilidad de skins y valores de preferencias (4.17).

## 4.1 — Red de seguridad propuesta

Pruebas JVM del gesto y sus thresholds (regla pura extraída preservando la fórmula exacta); invariantes del enum de estilos y claves persistidas; cobertura estructural del host/controles/queue/playback; ampliar `QueueWindowPlannerTest`. Lo que necesita Media3 real, drag/Compose o hardware es **test manual**, no se afirma cubierto por JVM.

## Reglas de cierre

Cada punto 4.x parte de commit verde; commit separado + tests + lint + APK; checklist teléfono; regresión de shuffle/repeat, skip, queue reorder, offline, Canvas, fullscreen y mini-player Glass ON/OFF. No eliminar duplicados funcionales por simple coincidencia visual.
