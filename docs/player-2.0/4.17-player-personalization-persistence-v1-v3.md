# 4.17 — Personalización, selectores, persistencia y compatibilidad V1/V3

Rama: `opentune-rebuild-v1`. Se mantiene la configuración existente del usuario.

## Diseño de la solución

```text
AppearanceSettings
  ├─ PlayerLayoutSelector        V1–V8
  ├─ PlayerBackgroundSkinSelector  DEFAULT/GRADIENT/CUSTOM/...
  ├─ PlayerButtonsSkinSelector   DEFAULT/SECONDARY
  └─ diálogo original SliderStyle
                      │
          DataStore histórico (sin nuevas keys)
                      │
        rememberPlayerPresentationPreferences
                      │
         PlayerPresentationPreferences
               ├─ designStyle   → PlayerLayout
               ├─ backgroundStyle → VisualSkin / fondos
               ├─ buttonStyle  → VisualSkin
               └─ sliderStyle  → PlayerSlider
```

## Cambios

- `ui/player/preferences/PlayerPresentationPreferences.kt`: lectura agrupada de las mismas cuatro claves que ya utilizaba el Player, sin migración de datos ni duplicar DataStore. Snapshot Compose inmutable reutilizado por Player y MiniPlayer.
- Defaults idénticos al Player anterior: diseño `V8`, fondo `DEFAULT`, botones `DEFAULT`, slider `Standard`. **No reescribe valores guardados**, incluidos `V1` y `V3`.
- `PlayerPresentationSelectors.kt`: los mismos `EnumListPreference` en selectores compartidos; mantienen textos traducidos para V1–V8 y todos los fondos y botones, incluida opción `GLOW_ANIMATED`. El origen de persistencia de las selecciones sigue en `AppearanceSettings`.
- `AppearanceSettings.kt`: usa los selectores anteriores con los callbacks DataStore originales; el acceso a `customize_background`, personalización de Canvas, sliders, modo oscuro, temas dinámicos, Liquid Glass y fullscreen permanece.
- V1/V3 conservan `PlayerLayoutFamily.CLASSIC`, sus controles en `PlayerComponents.kt`, las filas de Queue y sus rutas PlayerActions existentes.

## Claves preservadas

| Dato | DataStore key |
|---|---|
| Layout V1–V8 | `playerDesignStyle` |
| Fondo | `playerBackgroundStyle` |
| Estilo de botones | `player_buttons_style` |
| Slider | `sliderStyle` |

No se renombró ni se reseteó ninguna. No se renombraron valores de los enums persistidos. No existe un nuevo motor de skins paralelo al existente.

## Pruebas

`PlayerPresentationPreferencesIntegrationTest` verifica claves literales, defaults, enums V1–V8, lectura compartida, selector, callbacks DataStore, estilos V1/V3, fullscreen y personalización de sliders. Los contratos de PlayerLayout y VisualSkin también se mantienen.

Regresión de dispositivo: seleccionar V1 o V3, variar fondo, botones y slider, reiniciar aplicación y comprobar persistencia; rotar, cambiar entre V8 y V1/V3, probar Dynamic Color/dark mode/Glass y reproducir online/offline sin perder preferencias. Las pruebas fuente no sustituyen revisión de DataStore real.
