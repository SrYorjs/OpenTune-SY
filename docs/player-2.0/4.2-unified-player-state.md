# 4.2 — PlayerState unificado (presentación)

Rama: `opentune-rebuild-v1`.

## Objetivo

Un estado de presentación común para Player completo, MiniPlayer y futuros
`PlayerHost`/`PlayerLayout`, sin sustituir `PlayerConnection`,
`MusicService` ni el motor Media3.

## Arquitectura

```text
PlayerConnection StateFlows  ──┐
                                ├── PlayerStateInput
Existing Player.kt 100ms ticker┤   (pure, immutable snapshot)
Offline cover URI / seek preview┘          │
                                           ▼
                                       PlayerState
                                           │
                             ┌─────────────┴─────────────┐
                             ▼                           ▼
                      BottomSheetPlayer          NewMiniPlayerContent
                             │                           │
                   V1–V8 remains supported     Gesture/transport unchanged
```

`ui/player/state/PlayerState.kt` contiene `PlayerState`,
`PlayerStateInput`, `toPlayerState()` (función pura) y
`rememberPlayerState()` (adaptador Compose).

## Campos centrales

- `mediaMetadata`, `trackId`, `title`, `hasTrack`;
- `artworkUrl`: URI offline primero, thumbnail remoto después;
- `positionMs`, `durationMs`, `displayPositionMs`,
  `progressFraction` (0–1), `canSeek`;
- `playbackState`, `isPlaying`, `isBuffering`, `isLoading`;
- `canSkipPrevious`, `canSkipNext`, `shuffleModeEnabled`,
  `repeatMode`, `isLiked`.

Duraciones `C.TIME_UNSET`, nulas o negativas dan progreso 0,
sin NaN ni división por cero. La posición de previsualización del seek
no cambia la posición de reproducción real. Se clampa solo dentro de la
snapshot visual.

## Integración gradual

`Player.kt` sigue recolectando los flujos existentes, conservando
exactamente su ticker de 100 ms, manejo de crossfade, arrastre del seek,
persistencia y callbacks Media3. Se adopta el snapshot para loading,
`seekEnabled` y la portada V8 (manteniendo prioridad offline).

`MiniPlayerComponents.kt` crea el mismo snapshot desde sus flujos
actuales y utiliza metadata, isPlaying, favorito y isBuffering comunes.
MiniPlayer conserva loading solo en buffering, como antes.

V1–V8, Queue, Lyrics, Canvas, Fullscreen/AOD y Together no se
reescriben en esta etapa.

## Pruebas

- `PlayerStateTest`: mapping, artwork offline/remoto, cambio de
  metadata, progreso/desconocido, seek pendiente, buffering,
  shuffle/repeat/like/skip.
- `PlayerStateIntegrationTest`: consumidores y continuidad de ticker,
  crossfade/seek y separación de responsabilidades.
- Safety Gate: unit tests + Android Lint + universal debug APK.

### Prueba física requerida

Reproducción con V8 y otras skins; miniPlayer; slider/seek; canción
terminada; salto de pista; artwork offline, Canvas y descargas;
shuffle/repeat; pantalla completa, orientation, background y Glass
ON/OFF. En 4.2 no se pretende cambiar la apariencia.
