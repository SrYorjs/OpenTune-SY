# 4.14 — Migración del diseño V5 al Player unificado

Rama: `opentune-rebuild-v1`. Base verificada: 4.13 (`1f7deed`, Safety Gate verde).

## Objetivo y resultado

V5 deja de definir su composición compacta y sus gestos dentro de `Player.kt`
y de compartir un bloque de controles con V1/V3 dentro de `PlayerComponents.kt`.

```text
PlayerHost / PlayerState / PlayerProgress / PlayerActions
                          │
          PlayerLayoutFamily.COMPACT (V5)
                          │
  ┌───────────────────────┴─────────────────────────┐
  │                                                 │
V5PlayerContent.kt                          V5PlayerComponents.kt
  ├─ V5PlayerContent (ambas orientaciones)    ├─ V5PlayerTopActions
  ├─ V5LandscapeLikeBox (90° portrait)        └─ V5PlayerTransport
  └─ Modifier.v5OverlayGestures                         │
               │                                PlayerActions callbacks
        PlayerSeekSession
```

## Qué queda separado

- `V5PlayerContent`: tipografía de título de escala 56sp, tiempo 44sp,
  texto de artista y álbum, iconos y distribución compacta originales.
  Progreso y seek siguen usando `calculatePlayerProgress` de 4.9.
- `V5LandscapeLikeBox`: traslada sin retocar el layout de intercambio
  de restricciones, rotación de 90° y traducción del contenido.
- `v5OverlayGestures`: conserva doble toque según mitad superior/inferior,
  umbral `touchSlop`, timeout del sistema, arrastre vertical,
  condiciones de activación sobre el overlay de progreso y clamp del seek.
  Todas las intenciones siguen llegando a `PlayerActions` y
  `PlayerSeekSession`; crossfade permanece protegido.
- `V5PlayerTopActions`: conserva botones compartir/favorito de 36dp,
  iconos de 20dp, color y espaciado de 6dp que V5 compartía con V3.
  V3 conserva su implementación.
- `V5PlayerTransport`: conserva visualmente el bloque de 5 botones que
  V5 compartía con V1: repetición, anterior, play/pause, siguiente,
  favorito, con tamaños y springs de las etiquetas `playSizeV1V5`,
  `playAlphaV1V5`, `sideScaleV1V5`, `extraScaleV1V5`.
  V1 conserva el bloque heredado. El cambio de V5 no modifica V1.

## Compatibilidad

- El Player sigue manteniendo el ticker de 100ms, Media3 y cola originales;
  V5 no define nuevo motor ni ViewModel.
- Se conservan persistencia de estilo V5, MiniPlayer, personalización
  de fondos, música offline, shuffle/repeat y Together.
- No se modifican V2, V7 o V8 durante esta etapa.
- Los gestos físicos requieren regresión de dispositivo; las pruebas
  de contratos no sustituyen pruebas de interacción Android.

## Pruebas

`V5PlayerMigrationIntegrationTest.kt` protege ambos consumos V5,
rotación, doble toque, posición/seek, controles elásticos, estilos V1/V3,
y ausencia de duplicación de PlaybackEngine. Contratos heredados de
PlayerLayout, PlayerProgress, PlayerActions y PlayerSharedControls
se actualizan a los nuevos archivos propietarios.

Comprobar `testUniversalDebugUnitTest lintUniversalDebug assembleUniversalDebug`,
`assembleArm64Debug` y las pruebas físicas: gestos verticales/horizontales,
seek pausado, doble toque arriba/abajo, crossfade, rotación, mini,
temas, fondos y 50+ recomendaciones automáticas.
