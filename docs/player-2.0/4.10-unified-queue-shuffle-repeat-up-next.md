# 4.10 — Queue, Shuffle, Repeat y Up Next unificados (Player 2.0)

Rama: `opentune-rebuild-v1`. Punto anterior: 4.9.
Esta etapa centraliza las decisiones de presentación y las acciones del panel
Queue. **No introduce una segunda cola de reproducción.**

## Arquitectura

```text
Media3 / ExoPlayer  <—  QueueController / MusicService
       │                         │
       └── PlayerConnection (QueueWindows/Shuffle/Repeat/Index)
                     │
       ┌─────────────┴─────────────────┐
       ▼                               ▼
QueuePlaybackState              QueueActions
(presentación pura)           (intenciones de UI)
   ├── Played                     ├── toggleShuffle / toggleRepeat
   ├── Current                    ├── drag shuffle/unshuffled
   └── Up Next                    ├── remove / undo
                                 └── select / Together request
       │                               │
       └─────────────┬─────────────────┘
                     ▼
          Queue UI V1–V8 / Player
```

- `QueuePlaybackState.kt`: convierte el tamaño y el índice actual de
  `PlayerConnection.queueWindows` en una vista de posiciones reproducidas,
  actual y próximas. Las `queueWindows` ya vienen ordenadas mediante
  `Player.getQueueWindows()`, incluido shuffle; **no se vuelve a mezclar**.
- Con repeat-one, `nextIndex` indica la pista actual; con repeat-all, indica
  volver a la primera al terminar la última. `upNextIndices` no duplica filas.
- `QueueActions.kt`: adaptador pequeño que reutiliza `PlayerActions`
  para play/pause, shuffle y repeat y conserva la misma API de Media3
  para mover, eliminar, restaurar y reproducir una posición.
- En Together, una pulsación en otra pista por un invitado solicita
  `ControlAction.SeekToTrack`; si no tiene permiso, se deniega.
  El host conserva el seek directo sobre Media3.
- La vista `Queue.kt` mantiene el bloqueo de edición,
  selección múltiple, gesto swipe + deshacer, scroll, tiempos, estilos
  y `AutoLoadMoreKey`. El Player utiliza el orden compartido para
  seleccionar la miniatura de la pista siguiente.

## Límites y propietarios

- `QueueController` mantiene carga diferida, persistencia, `playNext`,
  `addToQueue` y la aplicación del shuffle al materializar páginas.
- `AutomixRadioController` sigue solicitando recomendaciones y ampliando
  la cola. No se sustituyen sus tareas ni sus políticas.
- `PlayerConnection` sigue escuchando cambios de timeline,
  repeat y shuffle. No se agregan flows ni tickers alternativos.
- `PlayerActions` mantiene la ruta de skip para Together y presencia.
- El orden para drag con shuffle conserva la estrategia anterior
  `DefaultShuffleOrder` aplicada a los índices físicos de las ventanas.
  Sin shuffle se utiliza `moveMediaItem` como antes.

## Pruebas y criterios de cierre

- `QueuePlaybackStateTest`: cola vacía, índice inválido, Up Next,
  repeat-one, repeat-all, shuffle y movimientos/índices inválidos.
- `QueueActionsTest`: delegación de toggles, selección, permisos Together,
  host, shuffle/reorder, eliminación y deshacer.
- `QueueActionsIntegrationTest` y contratos anteriores: uso compartido,
  límites entre UI/QueueController/Media3, protección de radio y Together.
- También se actualizan los contratos heredados que buscaban
  llamadas directas eliminadas por la nueva arquitectura.
- Safety Gate necesario: `testUniversalDebugUnitTest`,
  `lintUniversalDebug`, `assembleUniversalDebug`;
  finalizar con regresión de dispositivo. Publicar commits no equivale
  a aprobar las pruebas.

## Regresión manual (teléfono)

1. En Queue, cambiar shuffle y comprobar el orden real y el playback.
2. Ciclar OFF → ALL → ONE → OFF en Queue y en Player V1–V8.
3. Reordenar arrastrando con shuffle apagado y encendido; confirmar
   que no se pierden ni duplican pistas.
4. Eliminar una pista, tocar Deshacer y comprobar la posición restaurada.
5. Seleccionar pista futura y volver a la actual (toggle play/pause).
6. Cambiar entre Player y Queue: portada/siguiente y orden coinciden.
7. Probar permisos invitado Together, solicitudes y bloqueo de edición.
8. Llegar al final de 50 canciones y comprobar radio/autopaginación;
   después probar OFF/ALL/ONE.
9. Reiniciar aplicación para revisar restauración de cola;
   probar shuffle permanente y una cola descargada offline.
10. Repetir con V1–V8, MiniPlayer, pantalla bloqueada y durante crossfade.
