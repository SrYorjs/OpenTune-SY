# 3.15 — Migración gradual de Home / Search / Library / Settings

Rama: `opentune-rebuild-v1`. Migración controlada: NO sustituimos
la arquitectura de pantalla ni los componentes que contienen funciones
de reproducción, menus, descargas, navegación y preferencias.

- Home: HomeLoadingShimmer consume el estado de shimmer central. La sección global Deezer usa Artwork compartido, manteniendo su overlay de reproducción. Mantiene
  TextPlaceholder, LazyRow y GridItemPlaceHolder anteriores.
- Search universal: la carga inicial, carga paginada y sin resultados consumen
  OpenTuneLoadingState / OpenTuneEmptyState con el tamaño y padding anteriores.
  Se conservan búsqueda combinada, selector de calidad, versiones y paginación.
- Library Albums/Artists: las vistas LIST y GRID usan OpenTuneEmptyState y tokens de tamaño gridThumbnailHeight
  manteniendo iconos, textos y animaciones. SongListItem, AlbumGridItem
  y ArtistGridItem continúan como adaptadores funcionales hasta refactor específico.
- Settings: SettingsSearchEmpty reutiliza OpenTuneEmptyState.SETTINGS y
  conserva exactamente fondo, forma, icono, tipografía y subtítulo.

La migración de los estados comunes es real y funcional, pero los grandes
widgets con lógica de interacción NO se reemplazan a ciegas: 3.16 elimina
la duplicación segura y documenta la deuda restante.

Pruebas: Home shimmer, Search query/paging/quality, Library list/grid vacías,
Settings búsqueda sin coincidencias, mini-player, theme Glass ON/OFF.
