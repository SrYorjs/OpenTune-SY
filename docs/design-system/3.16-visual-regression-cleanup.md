# 3.16 — Duplicados visuales y regresión visual

Fecha: 2026-10-10
Rama: `opentune-rebuild-v1`

## Limpieza realizada

- La implementación antigua de `ui/component/EmptyPlaceholder.kt` ya
  NO reproduce un segundo árbol de Box/Icon/Text: delega exactamente
  en `OpenTuneEmptyState`. El nombre e import legacy se conservan para
  no romper pantallas restantes que aún lo llaman.
- `SettingsSearchEmpty` deja de implementar por separado su layout y
  utiliza la variante SETTINGS del estado común preservando todos los
  valores anteriores.
- `HomeLoadingShimmer` usa el único ShimmerHost por vía de
  `OpenTuneShimmerState`, conservando el contenido del esqueleto.
- `UniversalSearchScreen` sustituye loading/empty duplicados sin
  alterar búsqueda, paginación, calidad ni descarga.
- Las secciones Deezer globales de Home usan Artwork compartido en vez
  de un segundo renderer de portada/overlay con sus propios fallbacks.

## Componentes legacy conservados intencionalmente

No borrar todavía `SongListItem`, `LibraryAlbumGridItem`,
`LibraryArtistGridItem`, `FloatingNavigationToolbar`,
`LiquidGlassControls`, `BottomSheet`, `PlayerSlider`, `ChipsRow`
ni el API anterior de `liquidGlassSurface`: siguen teniendo
consumidores activos y, en varios casos, lógica de playback, menú,
navegación, configuración o gestos. Eliminarlos sin migrar la
funcionalidad causaría una regresión.

Los wrappers antiguos que ya delegan no mantienen una segunda
implementación visual. Los componentes pendientes de migración
requieren tareas específicas posteriores; no se presentan como
eliminados ni como reemplazados por un stub.

## Contrato automatizado

`VisualRegressionContractTest` valida:
- un único árbol para empty state;
- adopción del Design System en Home, Search, Library y Settings;
- continuidad de mini-player, Glass, navegación y selector de calidad.

Las pruebas de Kotlin/JUnit comprueban contratos y arquitectura,
NO comparan píxeles ni sustituyen screenshot tests de dispositivo.

## Matriz manual de regresión — para comparar antes y después

1. Search: consulta, sin resultados, progreso, paginación tras scrolling,
   resultados Deezer/Spotify/YTM y cambio de calidad/versión.
2. Home: chips, shimmer inicial, sección global Deezer, portada cargada,
   placeholder, play/pause y pulsación prolongada.
3. Library: Album/Artist lista y grid vacías/pobladas; cambiar filtros,
   vista, scroll y abrir context menus.
4. Settings: búsqueda sin coincidencias y volver, switches, sliders,
   ajustes de fuente, esquinas, color y glass.
5. Mini-player: corner 32dp con Glass OFF, bordes con Glass ON,
   swipe anterior/siguiente, transición de artwork y metadatos.
6. Navegación y overlays: rail si aplica, floating bar, bottomsheets,
   diálogo de playlist, overflow, back, focus/IME.
7. Accesibilidad: fuente grande, alto contraste, modo claro/oscuro/
   pure black y tamaños de pantalla distintos.

Antes de marcar Fase 3 al 100%, Gate COMPLETO verde (unit+lint+APK)
y conformidad de pruebas físicas. Registrar capturas comparativas
si se dispone de ellas; no se ejecutó comparación visual pixel a pixel.

## Riesgo y cierre

Cambios visuales mínimos e incrementales. La fase de limpieza elimina
duplicados verificables, NO borra implementaciones legacy activas.
La adopción exhaustiva de widgets complejos debe planificarse por
pantalla antes de su eliminación segura.
