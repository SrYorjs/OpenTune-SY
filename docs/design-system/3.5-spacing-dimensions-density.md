# 3.5 — Tokens de spacing, tamaños y densidad

Fecha: 2026-10-10
Rama: `opentune-rebuild-v1`

## Objetivo

Centralizar el espacio entre elementos y las dimensiones físicas compartidas
sin cambiar el diseño de OpenTune, el layout del reproductor, los radio de
esquina personalizables, la densidad del sistema ni las preferencias existentes.

## Arquitectura

```text
Shared spacing and size tokens (dp)
          ↓
ProvideOpenTuneDesignSystem
          ↓
OpenTuneDesignSystem.spacing / .sizes
          ↓
Search / reusable components

DefaultOpenTuneSizeTokens
          ↓
constants/Dimensions.kt (legacy adapter)
          ↓
Unmigrated screens / MiniPlayer / navigation

LocalDensity.current
          ↓
OpenTuneDesignSystem.density
          ↓
dp-to-px at interop/drawing boundaries only
```

## Spacing

La escala es `none=0`, `xxs=2`, `xs=4`, `sm=8`,
`md=12`, `lg=16`, `xl=24` y `xxl=32`, todo en dp.

Los valores excepcionales del layout actual mantienen nombres semánticos:

- `mediaRowPadding = 10.dp`
- `mediaRowArtworkGap = 14.dp`
- `mediaRowTextGap = 3.dp`
- `badgeHorizontalPadding = 8.dp`
- `badgeVerticalPadding = 5.dp`
- `qualityFilterGap = 6.dp`
- `searchBottomInset = 128.dp`

`searchBottomInset` conserva el comportamiento actual de Search; su
adaptación futura a insets variables corresponderá a la migración de pantallas.

## Sizes

`OpenTuneSizeTokens` tiene los tamaños compartidos ya existentes:
toolbar, mini-player, peek de cola, app bar, filas, thumbnail de listas,
cuadrículas, álbumes y padding horizontal de Player, además de los controles
de la fila de Search. Son los mismos valores que antes.

Para evitar duplicar la fuente de verdad, `constants/Dimensions.kt` delega
sus medidas fijas a `DefaultOpenTuneSizeTokens`. Se conservan sus nombres
públicos para mantener compatibilidad binaria/fuente con los consumidores
legacy en esta etapa.

No se modificaron `ThumbnailCornerRadius`, `GridThumbnailCornerRadius`,
`ThumbnailCornerRadiusKey`, `GridItemsSizeKey` ni tamaños de letras:
esos valores pertenecen a personalización/shapes o a las preferencias.

## Density

Los tokens se expresan como `Dp`, no como píxeles físicos. Compose
los transforma usando `LocalDensity.current` del dispositivo.

```kotlin
val density = OpenTuneDesignSystem.density
val artworkSizePx = with(density) {
    OpenTuneDesignSystem.sizes.searchRowArtwork.toPx()
}
```

Sólo usar conversiones `Dp -> px` para dibujo, gestos o interop Android.
No multiplicar `Dp` por `density` dentro de un layout Compose.
`fontScale` del dispositivo no debe alterar el tamaño físico de artwork:
sólo afecta al texto. No introducimos un selector nuevo de densidad.

## Primera migración y pruebas

`UniversalSearchScreen` adopta spacing de listas y filas, badges,
separación de artwork y tamaños de indicadores/botones, manteniendo
los valores originales exactamente.

`LayoutTokensTest` comprueba los tamaños legacy, la geometría de Search
y conversiones de densidad sin doble escalado.

Safety Gate: `testUniversalDebugUnitTest`, `lintUniversalDebug`,
`assembleUniversalDebug`. En dispositivo: verificar Search y el Player
en modos de fuente/tema y orientación disponibles.
