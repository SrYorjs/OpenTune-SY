# 3.3 — Sistema central de colores y roles semánticos

Fecha: 2026-10-10  
Rama: `opentune-rebuild-v1`

## Objetivo

Centralizar significados visuales propios de OpenTune sin reemplazar Material 3.

El `ColorScheme` actual sigue siendo la fuente de verdad para:

- dynamic color;
- custom palettes;
- dark mode;
- pure black;
- colores Material estándar;
- animación del theme.

El Design System añade una capa semántica para conceptos que Material no nombra
directamente.

## API

```kotlin
val colors = OpenTuneDesignSystem.colors
```

Roles introducidos:

```
surfaceGlass
surfaceGlassStrong

surfaceInteractive
surfaceInteractiveStrong
surfacePlayer

outlineGlass
outlineGlassStrong
shadowGlass

overlayScrim
overlayArtwork

textMuted
textSubtle

badgeAccent
badgeAccentStrong

accentPositive
onAccentPositive

accentWarning
onAccentWarning
```

## Reglas de uso

### Seguir usando MaterialTheme.colorScheme para

- primary / onPrimary;
- background / onBackground;
- surface / onSurface;
- error / onError;
- standard containers;
- standard outlines.

### Usar OpenTuneDesignSystem.colors para

- superficies de vidrio;
- borders del glass;
- overlays de artwork;
- scrims propios de la experiencia musical;
- texto de metadata atenuado;
- badges de proveedor/calidad;
- superficies interactivas propias;
- roles positivos/warning no modelados directamente por Material.

## Mapeo

Los roles no contienen un color de marca fijo.

Ejemplo:

```
badgeAccent = colorScheme.primary con alpha semántico
textMuted = colorScheme.onSurfaceVariant con alpha semántico
surfaceInteractive = colorScheme.surfaceContainerLow
accentPositive = colorScheme.tertiary
accentWarning = colorScheme.secondary
```

Esto permite que una paleta dinámica o personalizada cambie la apariencia sin
que cada feature deba recalcular sus colores.

## Compatibilidad Liquid Glass

Los valores de fallback usados anteriormente por el motor glass fueron
preservados al moverlos al Design System.

Dark:

```
surfaceGlass = white 7%
outlineGlass = white 18%
shadowGlass = black 18%
```

Light:

```
surfaceGlass = white 24%
outlineGlass = white 58%
shadowGlass = black 10%
```

Por tanto 3.3 centraliza estos valores sin buscar un rediseño visual del glass;
el rediseño óptico corresponde a 3.9.

## Migración inicial

3.3 migra dos consumidores para validar la capa:

1. `LiquidGlassBackdrop.kt`
   - fallback glass surface;
   - glass outline;
   - glass shadow.

2. `UniversalSearchScreen.kt`
   - metadata text muted;
   - provider badge accent surface.

El resto de pantallas se migrará gradualmente en 3.15 para no introducir una
reconstrucción visual masiva en una sola etapa.

## Pruebas

`ColorRolesTest` comprueba:

- equivalencia visual de glass dark;
- equivalencia visual de glass light;
- que roles semánticos sigan el Material ColorScheme;
- que no dependan de un color de marca fijo.

## Resultado

3.3 crea la única capa autorizada para nuevos colores semánticos de OpenTune.

Los colores directos legacy todavía pueden existir hasta 3.15/3.16, pero no se
deben añadir nuevos hardcodes cuando ya exista un rol equivalente.
